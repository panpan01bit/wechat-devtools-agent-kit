# 02 · 什么时候必须截图看电脑页面

结论先行：**这套流程里必须"看屏幕"的场景只有 5 类**，其余全部可以由 CLI / automator / a11y 树替代。

## ✅ 必须看（按出现频率排序）

### 1. IDE 阻断性弹窗（最常见）

**信号**：CLI 命令挂起无输出、automator 突然连不上、端口明明在听却没响应。

典型弹窗：版本更新提示、登录二维码过期、后台下载询问、项目信任确认。

**正确姿势**：先用 a11y 树（`get_app_state`）观察窗口——这些弹窗大多有可访问元素，
直接 element target 点「稍后再说 / 确定」，全程无像素。
只有弹窗是**自绘 canvas**（a11y 树为空）才截图。

### 2. 登录 / 扫码类（必须人参与）

开发者工具登录二维码、真机预览扫码确认、体验版身份验证。
这类不是"你看"，是**给用户看**——截图发给用户让他扫码。
能用 CLI 落盘的（`preview --qr-output`）不要截屏。

### 3. 视觉验收（任务本身就是"好不好看"）

改了 WXML/WXSS/设计系统，要确认渲染效果：

1. 优先 `miniProgram.screenshot({ path })` —— automator 直接截**模拟器画面**，
   不带桌面杂讯，脚本化可反复跑（这也算"看"，但走的是 MCP/连接器通道）。
2. 需要看整屏上下文（如 DevTools 面板布局）才桌面截图。
3. 细节看不清 → 截图后**局部放大**（crop），不要全屏眯着眼看。

### 4. 云开发控制台的图表

数据概览的 QPS/调用量曲线是自绘 canvas，a11y 树只有坐标轴文字。
要看**趋势形状** → 截图 + crop；只要数值 → 页面元素文本已经够了，不用截图。

### 5. 真机表现

体验版在手机上的表现没有任何通道可替代：让用户反馈或手机截图。
代理侧能做的是把问题在模拟器/automator 里先复现掉。

## ❌ 永远不要截图的场景（都有确定性替代）

| 想做的事 | 截图（错） | 正确通道 |
|---|---|---|
| 读代码/配置/报错文本 | 截屏 OCR | L0 文件读取 / 返回值 |
| 编译、上传、预览、部署云函数 | 点 IDE 菜单 | L1 CLI |
| 拿二维码 | 截屏识别 | L1 `--qr-output` 落盘 |
| 调云函数 / 读数据库 / 读 storage | 模拟器里点出来看 | L2 `mini.evaluate` |
| 复现一个 bug | 手工点页面 | L2 复现脚本 |
| 点 DevTools / 云控制台的按钮 | 找坐标点像素 | L3 a11y element target |
| 查调用是否成功 | 看界面红绿 | 云函数日志 / 返回 status |
| 确认文件生成/包体积 | 看进度条 | CLI 输出 / `ls -l` |

## 反模式清单

- **先截屏再点坐标**：正确顺序是先 a11y 观察拿 element target；坐标点击是最后兜底。
- **截屏读长文本/日志**：一定会抄错数字，直接读返回值。
- **重复观察同一状态**：observe 拿到 state_id 后直接 act；只有报 stale、动作后验证、
  怀疑界面变了才再次 observe。
- **stale frame 后原坐标重试**：界面已变，先重新 observe。
- **把"我想确认一下"当截图理由**：先问"返回值/日志里有没有这个信息"，有就不看像素。

## 一句话记忆

> 像素是给"人看的产物"和"自绘界面"用的；
> 代理之间传递信息用文字：返回值、日志、a11y 树、落盘文件。
